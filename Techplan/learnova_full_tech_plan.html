React 18 + Vite

Core UI framework + build tool

Why for Learnova

React's component model maps directly to Learnova's repeated UI — course cards, lesson rows, quiz questions are all reusable components. Vite replaces Create React App and gives you instant hot reload even with large codebases. React Router v6 handles the admin vs learner split cleanly.

Drawback

SEO gap — Public course pages render blank until JS loads. Search engines may not index your course catalog.

Fix — For a hackathon, ignore it. In production, add React Helmet for meta tags or migrate the public-facing routes to Next.js later.

Tailwind CSS + shadcn/ui

Styling + component library

Why for Learnova

shadcn gives you pre-built accessible components you actually own — the quiz builder dialog, lesson editor popup, reporting table with column toggles, and kanban board all need complex UI that shadcn handles without fighting you. Tailwind keeps styles local so you never have CSS conflicts between admin and learner UI.

Drawback

Learning curve — shadcn requires understanding Radix UI primitives. The first dialog/sheet component takes time.

Fix — Use the shadcn CLI to add components one at a time. Start with Button, Dialog, and Tabs — you'll use these everywhere.

React Player

Video lesson player

Why for Learnova

The spec requires YouTube and Google Drive video embeds in the full-screen player. React Player handles both URLs with a single component and zero configuration. Handles progress tracking callbacks needed for marking video lessons as complete.

Drawback

Google Drive — Drive embeds break when the file sharing settings change. Private files show an error.

Fix — Show a warning in the lesson editor when a Drive URL is entered. Recommend YouTube uploads for reliability.

Zustand

Client-side UI state

Why for Learnova

Manages ephemeral state that doesn't need to hit the server: current quiz answers before submission, sidebar open/closed in the full-screen player, active lesson index, points popup visibility. Far simpler than Redux — a Zustand store is just a plain JS object with setters.

Drawback

No persistence — If the learner refreshes mid-quiz, their in-progress answers are lost.

Fix — Use Zustand's persist middleware to save quiz state to localStorage as a backup. On quiz start, check localStorage before initializing fresh state.

TanStack Query

Server state + API cache

Why for Learnova

Every API call in Learnova — course list, learner progress, reporting data — needs caching, loading states, and error handling. TanStack Query gives all three automatically. Marking a lesson complete triggers an optimistic update so the UI feels instant, then syncs with the server in the background.

Drawback

Stale reporting — The instructor reporting dashboard may show cached data that's minutes old when multiple learners are active.

Fix — Set staleTime: 0 and refetchInterval: 30000 on the reporting query so it auto-refreshes every 30 seconds.

Python FastAPI

REST API server

Why for Learnova

FastAPI is async-native, meaning it handles multiple simultaneous learners saving progress without blocking. Auto-generates API docs at /docs — invaluable when building both frontend and backend simultaneously. Pydantic models validate quiz payloads, course forms, and enrollment data automatically.

Drawback

Async pitfall — Mixing sync SQLAlchemy calls inside async FastAPI routes causes deadlocks and slow responses.

Fix — Use SQLAlchemy's async session (AsyncSession) throughout, or use run_in_executor to safely call sync DB code from async routes.

SQLAlchemy + Alembic

ORM + database migrations

Why for Learnova

SQLAlchemy maps your Python classes directly to database tables — Course, Lesson, Quiz, Progress, Enrollment. Alembic handles schema migrations so when you add a new column (like badge_level to users), it updates the DB without destroying existing data.

Drawback

Migration conflicts — If two developers add migrations simultaneously, Alembic's history chain breaks and you get errors on deploy.

Fix — One person owns migrations during the hackathon. Always run alembic upgrade head before starting work each session.

JWT + bcrypt

Authentication + passwords

Why for Learnova

Three roles (Admin, Instructor, Learner) need different access levels. JWT tokens carry the role claim so every API route can check permissions without hitting the database. bcrypt hashes passwords securely on registration. python-jose handles JWT encoding/decoding.

Drawback

No token revocation — If an instructor is removed, their JWT stays valid until it expires. No instant logout across devices.

Fix — Keep token expiry short (1 hour). For a hackathon this is acceptable. In production, add a Redis-based token blocklist.

PostgreSQL

Primary database

Why for Learnova

Handles concurrent quiz submissions from multiple learners. ACID transactions ensure that when a quiz completes, the score, total points, and badge level all update atomically — never partially. The reporting dashboard runs complex JOINs across users, courses, and progress that PostgreSQL optimizes well. You already have it via pgAdmin 4.

Drawback

Local-only risk — Your pgAdmin 4 runs locally. If you demo on a different machine, there's no database.

Fix — Push to Neon (free cloud PostgreSQL) before any demo. Keep local DB for development, Neon for the live presentation. One env variable swap.

pgAdmin 4

Database GUI (dev only)

Why for Learnova

Lets you visually inspect tables during development — check that quiz attempt records are saving correctly, verify progress percentages are calculating right, write ad-hoc SQL to test reporting queries before building the API. Huge time saver when debugging data issues.

Drawback

Dev tool only — pgAdmin is not part of the deployed app. It only helps you locally.

Fix — That's by design — it's your development companion, not production infrastructure. Use it freely.

Cloudflare R2

File storage for uploads

Why for Learnova

Course cover images, lesson PDFs, document attachments, and additional resources all need object storage. R2 has zero egress fees (unlike S3) which matters when learners frequently download PDFs. S3-compatible API means you can use boto3 in Python with minimal config change. Free tier: 10GB storage.

Drawback

Setup overhead — Requires a Cloudflare account, bucket config, and API tokens. More setup than saving files to disk.

Fix — For the first day of hacking, save uploads to a local /uploads folder. Swap to R2 before the demo with one boto3 client change.

Resend

Transactional email

Why for Learnova

The spec requires "Add Attendees" (invite by email) and "Contact Attendees" wizards. Resend's Python SDK sends emails in 3 lines of code. Free tier handles 3,000 emails/month — more than enough for a hackathon demo. Much simpler than configuring SMTP servers.

Drawback

Domain verification — Without a verified domain, emails land in spam or are limited to test addresses only.

Fix — Use Resend's sandbox mode for demos — it logs emails without actually sending them. Verify a domain only if real delivery is needed.

Vercel

Frontend hosting

Why for Learnova

Connects to your GitHub repo and auto-deploys on every push. React + Vite apps deploy in under 2 minutes. Free tier, global CDN, custom domains. For the hackathon demo, push once and share the URL.

Drawback

Frontend only — Vercel cannot host your FastAPI backend. They are separate deployments.

Fix — Deploy FastAPI to Railway or Render (both free tier). Set VITE_API_URL in Vercel's environment variables to point to your Railway backend URL.

Railway

Backend + DB hosting

Why for Learnova

Deploys Python apps from a Procfile or Dockerfile with zero configuration. Free $5/month credit is enough for a hackathon. Can also host a PostgreSQL instance, giving you a cloud DB with one click — or point it at Neon for dedicated managed Postgres.

Drawback

Cold starts — Free tier apps sleep after inactivity. First request after sleep takes 10–20 seconds.

Fix — Use UptimeRobot (free) to ping your Railway URL every 5 minutes — keeps it warm. Or upgrade to paid ($5) the day of the demo.

Neon

Cloud PostgreSQL

Why for Learnova

Serverless PostgreSQL with a generous free tier (0.5GB storage). You develop locally with pgAdmin 4, then swap one DATABASE_URL environment variable to point to Neon for the live demo. Your schema and data migrate instantly with alembic upgrade head.

Drawback

Also sleeps — Neon's free tier pauses the database after 5 minutes of inactivity, adding latency on first query.

Fix — Same UptimeRobot trick works. Or keep one API endpoint as a health check that Railway pings, which in turn wakes the Neon DB.
